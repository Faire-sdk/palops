# antislop audit 001: PalOps

Date: 2026-10-23
Mode: AFTER (audit only, nothing changed yet)
Commit audited: `main` at 21a0bbb. The unmerged ban window branch (`claude/task-j1gkuc`) was not audited.

Numbering is shared with the PalBan Network audit of the same date: PalOps uses 1 to 15, PalBan uses 16 to 25. Pick numbers from either list.

## How this was checked

- axe-core 4 on 26 views (public site, login, every panel page and tab, the ban and profile dialogs), in light and dark, at 1300px and 390px wide.
- `contrast-check.py` from antislop-human on every theme color pair, including placeholders and borders that axe skips.
- Keyboard: tabbed through Players, Bans and Settings in both themes and read the computed focus style of every stop.
- Tap targets measured at 390px on the public site, Dashboard, Players, Bans and World map.
- Code search for em dashes, removed outlines, hard-coded content and route states.

What passed: no horizontal scroll at 390px on any view, no `outline: none` in the code, every page has loading and error handling, every dialog closes with Escape, no buzzwords, and the public site passed axe with no issues.

## Findings

Priority follows the rule tier: Hard Gate is HIGH, Purpose-Gate is MEDIUM, Quality Locks are LOW. Findings that rest on C-4 (the craftsmanship standard has no tier) are rated by impact and say so.

### HIGH

**1. R-25: Light theme text below 4.5:1**
Several theme colors fail as text on white.
- Active sidebar item, `#0b6bcb` on `#ebebeb`: 4.42 (every panel page)
- Warning text `#ed6c02` on white: 3.11 (Signals chips, Performance tab), and 2.85 on `#f5f5f5` (Console warning lines)
- Info text `#0288d1` on white: 3.85 (Signals)
- Secondary `#00897b` on white: 4.31 (Dashboard)
- Input placeholders, MUI default `#a2a2a2` on white: 2.55 (every search field)

Fix: set light mode values in `web/src/theme.ts` and check each one. Checked candidates: warning `#b45309` (5.02 on white, 4.61 on `#f5f5f5`), info `#0277bd` (4.80), secondary `#00796b` (5.32), a lighter selected-item background such as `#f0f4fa` (4.78), and a darker placeholder.

**2. R-25, R-34: White on red buttons in dark mode, 3.68:1**
The dark theme's error red `#f44336` carries white text on the two Ban buttons on the Bans page (`web/src/pages/BansPage.tsx:180`, `207`), the confirm button in the player ban dialog, and the red button on the Server page (`web/src/pages/ServerPage.tsx:208`).
Fix: dark mode `error.main` of `#d32f2f` (4.98 with white) or `#c62828` (5.62).

**3. R-32: Focus indicator is nearly invisible**
The theme sets no focus style, so focus shows as MUI's 12% tint (about 1.3:1 on white) or a ripple pulse. On Players, 30 of 39 tab stops had no outline or ring. On the sidebar the focus tint is fainter than the selected item, so you cannot tell where focus is.
Fix: one `:focus-visible` outline (2px, primary color, 2px offset) for buttons, links, tabs, chips and inputs in `theme.ts`. Primary passes 3:1 in both modes (`#0b6bcb` on white 5.28, `#6ab7ff` on `#161d23` 7.97).

**4. R-32: No skip link**
Every panel page puts 11 sidebar links and the header controls before the content, so a keyboard user tabs about 14 times to reach the page.
Fix: a "Skip to content" link as the first focusable element, visible on focus.

**5. R-32: World map markers work with a mouse only**
Player and base markers open the profile or the base's workers through `onClick` on an SVG group with no `tabIndex`, role or key handler (`web/src/components/WorldMap.tsx:344` to `405`). The hover card opens on pointer enter only (`WorldMap.tsx:190`). Panning is drag only. The Players and Bases tabs give a partial alternative, but the map itself cannot be used from the keyboard.
Fix: make clickable markers focusable buttons (Enter and Space open them), show the hover card on focus, and pan with the arrow keys.

**6. R-32: Scroll areas the keyboard cannot reach**
The Console output box and the Logs table container scroll, but nothing inside them takes focus, so a keyboard user cannot scroll them.
Fix: `tabIndex={0}` and an `aria-label` on both containers.

**7. R-03: Tap targets under 44px on phones**
At 390px wide: 6 of 6 controls on Dashboard, 14 of 19 on Players, 10 of 10 on Bans and 14 of 21 on World map are smaller than 44px. Examples: menu button 40x40, Export CSV 110x31, filter chips 24px tall, Unban 64x31, player name links 20px tall.
Fix: in `theme.ts`, under `@media (pointer: coarse)`, give buttons, icon buttons, chips and table links a 44px minimum hit area. Desktop sizes stay as they are.

**8. R-02: Em dash used as the empty value**
76 places in `web/src` show an em dash (U+2014) when a value is missing (for example `web/src/components/PlayerActions.tsx:215` to `218`, `web/src/components/FpsHistory.tsx:29`). One more sits in a code comment (`server/src/services/palworld/types.ts:28`).
Fix: words that say what is missing ("None", "Never", "Not set"), from one shared helper. PalBan already uses "None".

**9. R-38: Generic rules on every public site**
The public home page lists four rules hard-coded in `web/src/site/HomePage.tsx:204` to `217`. Every PalOps install shows them, including servers whose owners never wrote them.
Fix: owner-editable rules in Settings, and hide the section until rules are set.

**10. R-37 (and R-31): No written design direction**
The repo has no `DESIGN.md` or UI conventions section. The only direction on record is "no pills", given in chat. The light palette sits close to MUI's defaults, and no reasons are written down for color, type or layout.
Fix: needs you. A short UI conventions section like the one in PalBan's `CLAUDE.md`: palette, type, corners, badge style, what each status color means. I can write it down from your answers; I will not invent it.

### MEDIUM

**11. C-4 (rated MEDIUM): Screen reader semantics**
- The read-only input in Settings > Discord has no label (axe: critical).
- `aria-label` sits on plain `div`, `g` and `circle` elements (activity bars on Players > Activity, the world map, profile dialog charts: 64 nodes). Screen readers ignore it there, so chart values only appear in hover tooltips.
- The sidebar `<ul>` holds `<a>` elements directly instead of list items (every panel page).
- Action columns have empty header cells (Bans, Players, Signals, Settings > Users, Performance).
- Headings jump straight to `h6` subtitles (Activity, Server, Settings > Console, Settings > Discord).
- The login page has no `main` landmark.

Fix: label the input, give charts `role="img"` with a text summary, render the sidebar as list items, add visually hidden "Actions" headers, fix heading levels, wrap login in `main`.

**12. C-4 (rated MEDIUM): Input borders below 3:1**
Text field outlines are MUI's default: `#c4c4c4` on white is 1.74:1, about `#4c5156` on `#161d23` is 2.15:1. Non-text UI needs 3:1.
Fix: a darker outline in the theme (for example `#8c8c8c` on white, 3.36; `#7a8288` on `#161d23`, 4.36).

**13. R-06: Uppercase tracked labels with no written reason**
`overline` labels in `web/src/components/common.tsx:120` and `web/src/components/UserProfileDialog.tsx:178`.
Fix: sentence case, or write the reason in the design direction (finding 10).

### LOW

**14. R-05: "How to join" in the three-step template shape**
Three numbered round avatars (`HomePage.tsx:189` to `201`). Only two steps are about joining; the third (sign in with Discord) is optional.
Fix: a join card with the server IP, a copy button, and one line about signing in.

**15. R-21: No way to pick the theme**
PalOps follows the system setting only. A player on a light OS who wants dark (or the reverse) has no switch.
Fix: a light, dark, system switch in the header, remembered per browser. Both modes must then pass findings 1 and 2.
